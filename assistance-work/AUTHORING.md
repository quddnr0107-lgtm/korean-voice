# 보조설명 작성 입력 계약

이 폴더는 원문을 읽고 실제 모델이 설명을 작성하기 위한 입력이다. 자동 생성 설명이나 승인된 새 설명은 들어 있지 않다. 원문 스냅샷은 제80회 / 27년 전반기이며 `inventory.json`의 Git blob SHA와 SHA-256이 기준이다.

## 파일

- `inventory.json`: 원문 수·조문 수·중복·표 표시 상태·49개 입력 묶음 목록.
- `source/study_data.json`: 실제 원문 바이트 스냅샷.
- `rows.jsonl`: 본문 6,073행을 원문 순서대로 수록. `sourceIndex`, `occurrence`, `sourceId`는 누락 없이 고유하다.
- `articles.jsonl`: 법령·회차·위계·조문별 850개 조문. 제목을 포함한 모든 원문 행과 참조 후보가 있다.
- `shards/*.jsonl`: 법령·위계별 조문 묶음. 각 JSONL 줄은 조문 하나이고, 조문 중간은 자르지 않는다. 최대 150개 본문 행이다. 작은 위계 및 마지막 큰 조문 때문에 100행 미만인 묶음은 inventory에 그대로 드러난다.
- `external-references.jsonl`: 현재 원문에 없거나 소속 법령이 확정되지 않은 인용. 정답으로 취급하지 않는다.
- `appendix-review.jsonl`: 표 낭독 본문·숨김 행·appendix 플래그 행과 앞선 표 앵커 후보. 기존 낭독 자료는 새 설명의 검토를 대신하지 않는다.

## 작성할 결과 한 행

```json
{"sourceId":"입력의 sourceId","sourceIndex":123,"text":"원문을 한두 문장으로 풀어 쓴 실제 설명","references":[{"articleIdentity":"법령|회차|위계|조문","sourceId":"실제로 읽고 풀이에 사용한 행"}],"notes":[]}
```

`sourceId = sha256(UTF8(JSON.stringify([law,period,type,String(articleNum),original,occurrence])))`이며 occurrence는 동일한 법령·회차·위계·조문·원문 전체 문자열 안의 0부터 시작하는 발생 순서다. sourceIndex는 고정 스냅샷 DATA.blanks의 0부터 시작하는 위치다. 원문은 수정하지 않는다.

## 읽고 쓸 때

1. 대상 조문 전체와 상위 항·호의 주어·효과를 읽는다. 호·목 하나만 떼어서 의미를 만들지 않는다.
2. 번호만 적힌 참조는 실제 대상의 내용으로 풀어 넣는다. `referenceCandidates`는 위치를 찾기 위한 기계 추출이며 검증된 해석이 아니다. 같은 법·같은 항·전항·각 호·범위 나열은 원문의 문맥을 대조한다.
3. 필요한 인용이 다른 법령에 있거나 시험 범위 자료에서 빠져 있으면 공식 원문을 확보한다. 모르는 인용의 뜻을 추측하지 않는다. 미해결 참조를 notes에 기록하고 검토 완료로 표시하지 않는다.
4. 설명은 원문 문단 바로 아래에서 다시 읽을 수 있는 한두 문장으로 작성한다. 주체, 대상, 조건, 기간·금액·연령·인원, 시작점·끝점, 예외, 반드시 해야 함·할 수 있음·할 수 없음의 효과를 유지한다. 숫자나 법적 효과를 요약 과정에서 바꾸지 않는다.
5. 법령에 없는 입법 취지나 추측성 이유를 덧붙이지 않는다. 기존 개념강의와 합본강의는 문맥을 찾는 참고 자료이며, 문장을 그대로 잘라 붙였다는 이유로 검토가 끝나는 것은 아니다.
6. '이 조문에 관한 내용입니다', '규정에 따라 처리한다는 뜻입니다' 같은 공통 문구, 조사 치환, 원문 복사만으로 완료 처리하지 않는다.
7. 195개 숨김 원문 행과 52개 표 낭독 대체 행은 별도로 검토한다. 깨진 OCR 조각을 완성된 문장인 것처럼 설명하지 않는다. 표 전체 설명으로 포함할 경우 어느 원문 행을 어느 표 앵커가 설명하는지 명시하고, raw coverage와 실제 표시 coverage를 따로 계산한다.
8. 같은 원문 문자열이 다른 조문에 있어도 주어·상위 항·예외가 다를 수 있다. 서로 다른 sourceId의 설명을 일괄 승인하지 않는다. 같은 조문의 동일 원문 3쌍도 독립적인 발생 위치를 보존한다.

## 검토 게이트

- sourceId 집합·sourceIndex·원문 전체·occurrence·본문 수가 스냅샷과 일치해야 한다. 누락·중복·범위 밖 ID는 실패다.
- 설명의 숫자·단위·비교 연산(이상/초과/이하/미만), 기간 기산점, 의무·재량·금지·예외는 대상 원문과 실제 사용한 참조 원문을 함께 대조한다. 새 숫자가 참조 원문에서 온 것인지 확인하므로 단순 숫자집합 동일검사는 충분하지 않다.
- 작성과 다른 검토 단계에서 한 행씩 원문·설명·실제로 사용한 참조를 다시 읽는다. 숫자·주체·조건·효과를 바꾼 음성 대조군을 넣어 기계 검사도 의미가 있는지 확인한다.
- 검토가 끝나기 전에는 `reviewed`, `approved`, 전체 완료 또는 F1 오디오 생성 대상으로 올리지 않는다. 숫자 누락 없이 6,073개 JSON 객체가 있다는 것은 내용 정확성의 증거가 아니다.
