## 스레드 비교

[실제 실행](https://github.com/quddnr0107-lgtm/korean-voice/actions/runs/43388953710)의 CPU는 AMD EPYC 7763, 4 vCPU였다. 하나의 모델을 메모리에 유지하고 두 짧은 공개 문장을 각각 4/2/1, 1/2/4 순서로 합성했다. inter-op은 모든 조건에서 1이다. 운영 코드는 intra-op 4만 명시하므로 이번 기준 조건이 운영의 모든 스레드 환경과 동일하다는 주장은 하지 않는다.

6개 모두 자연 종료와 신호 검사를 통과했고, 별도 고정 Whisper-small에서 canonical 문자 오류가 0이었다. 4↔2 비교 중 한 문장은 PCM 데이터까지 동일했다. 다른 문장은 같은 샘플 수에서 극소수의 수치 차이만 보였다. WAV 컨테이너의 PEAK timestamp 때문에 PCM이 같아도 파일 전체 SHA가 달라질 수 있음을 따로 확인했다. talker가 반환한 첫 코드열 해시는 같았지만, 전체 코드북 동등성이나 사람의 청취 승인으로 확대하지 않는다.

두 문장·단일 CPU 시험이므로 303강의 확정 단축률이나 다른 CPU의 성능을 뜻하지 않는다. 코드와 수치는 [스레드 증거](evidence/cpu-thread-43388953710.json), [독립 ASR 증거](evidence/cpu-thread-43388953710-asr-check.json)에 남겼다.

## 배치와 캐시

[배치 실행](https://github.com/quddnr0107-lgtm/korean-voice/actions/runs/43389825340)은 Intel Xeon 6975P-C에서 단일과 배치를 같은 resident FP32 모델로 비교했다. 스레드 실험과 CPU가 다르므로 두 실행의 절대시간을 직접 비교하지 않는다. 배치의 생성 난수 순서가 달라 개별 문장의 같은 seed나 같은 출력을 보장하지 않는다. 정상 EOS·실제 패딩·codec 프레임·PCM 길이는 4개 모두 확인했다. ASR은 단일에서 0/1자, 배치에서 0/0자 차이를 보였다. 이는 실제 발음 오류와 ASR 오류를 구분하는 증거가 아니다. 음성 길이가 길어져 RTF가 좋아진 것을 강의 제작이 1.39배 빨라졌다고 표현하지 않는다. [배치 증거](evidence/cpu-batch-43389825340.json), [독립 ASR](evidence/cpu-batch-43389825340-asr-check.json).

[캐시 실행](https://github.com/quddnr0107-lgtm/korean-voice/actions/runs/43390521891)은 별도 runner 3개에서 원래 다운로드·크기/JSON 검사·원래 renderer 해시 검증을 포함한 경로와 새 캐시 복원·준비·모든 검증을 비교했다. 공개 모델 15개, 5,006,371,958바이트의 SHA가 모두 맞았고 실제 cache hit였지만, 복원 구간만 36.505초였다. 이 캐시안은 운영 workflow에 넣지 않는다. [캐시 증거](evidence/public-cache-43390521891.json).

## 운영 상태와 적용 경계

이번 변경은 공개 성능시험과 증거 저장이다. 운영 renderer·recipe·request·조립 및 QA 기준은 바꾸지 않았다. 통과한 27구간과 차단된 31구간을 재합성하거나 덮어쓰지 않았고, 새 완성 강의나 배포를 주장하지 않는다.

운영은 현재 4스레드와 하나의 설정 지문을 고정한다. 2스레드를 한 줄로 바꾸면 설정/코드 지문이 달라져 기존 통과 구간이 재사용 대상에서 빠질 수 있다. 따라서 2스레드의 다음 적용에는 기존 27구간의 원래 지문과 검증을 보존하는 호환 처리가 필요하다. 기존 receipt를 새 설정으로 바꿔 적거나 검수 기준을 낮추는 방식은 쓰지 않는다.

현재 전체 로컬 회귀: 251개 실행, 250개 통과·기존 1개 건너뜀. 세 공개 실행은 모두 성공했다.
